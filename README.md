# raman-plot-skill

用 **COM 控制本机已打开的 Origin** 绘制碳材料拉曼单谱（D 带 / G 带），一键产出 **300 dpi TIF** + **Origin 工程源文件（.opju）**，图上自动标注 **I_D/I_G**。

---

## ⚠️ 请先读：适用范围与局限

**这个 skill 只适用于碳材料的 D 带 / G 带拉曼谱。它不是通用拉曼绘图工具。**

| 限制 | 说明 |
|---|---|
| **X 轴固定 1000–2000 cm⁻¹** | 只覆盖 **D 带（~1350 cm⁻¹）** 和 **G 带（~1580 cm⁻¹）**。**其他拉曼振动峰不在绘图所选区间内** |
| **只认两个峰** | 拟合固定为「常量基线 + 两个 Gaussian」，峰位约束 D 1280–1450、G 1500–1650。谱上多于两个峰，或峰不在这两个窗口内，结果无意义。 |
| **只报 I_D/I_G** | 不做峰位/半高宽/晶粒尺寸的正式报告，不做去卷积与分峰归属。 |
| **依赖本机 Origin** | 必须已安装 OriginPro 2021 并**处于打开状态**，仅 Windows。 |

要用于其他材料，需要改：`raman_plot.py` 的 X 轴范围（命令行第 3、4 个参数可临时覆盖）、`origin_plot.box_axes` 的 `xinc`、以及 `raman_fit.recipe_A` 的峰位窗口与峰数。

---

## 它能做什么

```
txt 两列数据  ──►  Origin 里建表 + 成图  ──►  20261023-1-a.tif   (300 dpi, 紧凑页边距)
                                           20261023-1-a.opju  (Origin 工程，可继续编辑)
```

- 样式是**逐条确认过的定稿**：X 轴 1000–2000 主刻度 500 / 次刻度 250，Y 轴无刻度，上右轴封闭成框，低饱和绿 `#CEF297` 细线，图例右上，图例下方一行 `I_D/I_G=X.XX`。
- **出图前自动做视觉验证**：把图例和标注临时挪出页面渲染一次，数原位置有没有深色像素，确认没压在曲线上；不通过就自动换位置，再不过就停下不出图。
- **绝不覆盖已存在的 `.opju`**（曾经无脑 Save 把一份 1.5 MB 工程覆盖成 35 KB，Origin 没有自动备份，不可恢复）。

## 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows |
| Origin | **OriginPro 2021，且已经打开、窗口可见** |
| Python | 3.9+ |
| 依赖 | `pip install pywin32 numpy scipy Pillow` |

Origin 必须**先手动打开**。脚本用 `win32com.client.Dispatch("Origin.ApplicationSI")` 连正在运行的实例，不会自己启动一个隐藏进程。
（`GetActiveObject` 会报 `com_error -2147221021`，这是正常的，不要改用它。）

## 快速开始

```bash
# 1. 装依赖
pip install pywin32 numpy scipy Pillow

# 2. 打开 OriginPro 2021（保持窗口可见）

# 3. 出图（txt 是两列 ASCII：拉曼位移、强度）
python raman_plot.py 20261023-1-a.txt
```

输出到脚本同目录：

- `20261023-1-a.tif` —— 交付图，300 dpi，页边距紧凑
- `20261023-1-a.opju` —— Origin 工程源文件，含数据表和成图

### 参数

```bash
python raman_plot.py <数据.txt> [输出名主干] [x下限] [x上限]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `数据.txt` | 必填 | 两列 ASCII（空格或制表符分隔），x 降序升序都行，脚本会排序 |
| `输出名主干` | = txt 主干名 | **命名规则：txt 叫什么，tif 和 opju 就叫什么**，只换扩展名 |
| `x下限` / `x上限` | 1000 / 2000 | 临时覆盖 X 轴范围 |

`--force` 才会覆盖已存在的同名 `.opju`。

## 数据格式

```
2500.8	594.5
2499.3	601.2
...
500.5	2462.0
```

两列、无表头、空格或制表符分隔即可。第一列拉曼位移，第二列强度（a.u.）。

## 交付物规范

| 交付物 | 规格 |
|---|---|
| `<名>.opju` | Origin 工程，含数据表 + 成图 |
| `<名>.tif` | 300 dpi，页边距紧凑（四周 150 设备单位 = 0.25 in = 75 px） |

## 拟合口径

- 全谱 + **常量基线**（自由参数）+ 两个 Gaussian —— 与 Origin 自带 Peak Analysis 一致。
- 峰位约束：D 1280–1450，G 1500–1650；FWHM D 40–400，G 30–200。
- `I_D/I_G = h_D / h_G`（**从基线算起的峰高**，不是面积比）。
- **图上不画任何拟合曲线**，拟合只是为了读出峰高。
- 报数保留**两位有效数字**，四舍六入五成双（`raman_fit.sig2()`）：0.6790 → 0.68，0.5486 → 0.55。

口径必须在报告里写明 —— 换窗口 / 基线 / 线型，I_D/I_G 最多能差 20%。

## 文件

| 文件 | 作用 |
|---|---|
| `raman_plot.py` | 入口。读数据 → 拟合 → 建图 → 视觉验证 → 导出 TIF + 保存工程 |
| `origin_plot.py` | `OriginPlot` 类，COM 封装（建表、成图、样式、裁边、导出、重叠检测） |
| `raman_fit.py` | 拟合与报数，`recipe_A` / `recipe_B` / `sig2` |
| `SKILL.md` | 给 AI agent 用的完整操作说明与踩坑表 |

## 给 AI agent 用

把 `SKILL.md` 放进 agent 的 skills 目录（例如 `~/.dsh/skills/raman-plot/SKILL.md`），
agent 就会在用户要求「把拉曼 txt 画成图」时自动调用，并遵守：

- 出图前必须做视觉验证（图例 / 标注不能压在曲线上）
- 出图后必须问用户是否满意；不满意就把 `.opju` 打开让用户自己微调
- 绝不覆盖已存在的 `.opju`
- `.tif` / `.opju` 的命名跟 txt 完全一致

## 已知坑（详见 SKILL.md）

| 坑 | 现象 |
|---|---|
| `app.Save()` 无参数 | 返回 False，什么都不做 |
| `app.Save("D:/.../x.opju")` 正斜杠 | 被拼到 `Documents\OriginLab\User Files\` 下，弹「文件正在使用」框，**卡死后续所有 COM 调用** |
| `tr1.DPI:=300` | 整条 `expGraph` 失败，不生成文件（tif 默认就是 300 dpi，不用设） |
| `o.Show = False` | 对 `expGraph` 无效，对象照旧渲染 —— 检测重叠必须改坐标 |
| `trim_page()` 之后再摆图例 | 必须先改 `page.width/height` 再重算 `layer` 百分比，且 trim 后绝对坐标会错位，得重摆一次 |
| `expGraph` 静默失败 | 导出前必须 `win -a "图名"` 激活目标页 |
| 残留 `#32770` 模态框 | `app.Pages(i)` 抛 `com_error -2147418113` |
